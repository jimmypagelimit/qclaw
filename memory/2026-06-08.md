## year-filter 修复（两次迭代）
- **问题 1**：年份筛选 `JOIN listen_history` 只返回有收听记录的专辑，2026 年 60 张只返回 ~40 张。改成 `release_year`（LEFT JOIN），全部返回但不包含海朋森等非 2026 年发行的专辑
- **问题 2**：用户指出海朋森等专辑搜不到了。改回 `listen_year` + INNER JOIN + GROUP BY，同时修复 GROUP BY 缺失导致的 SQL 500 错误
- **最终方案**：`listen_year` + `INNER JOIN (listen_history GROUP BY album_id)` + `GROUP BY a.album_id`

- **关键教训**：年份筛选按**收听年份**而非发行年份，因为用户找的是"某年听过什么"

## 16:02 - 用户批评：album-tracker 核心查询改动犯了三错

用户原话："我发现你犯的错误可太多了，这是最重要的项目，你可得长点心"

**三个错误：**
1. 没想清楚就动手 → 第一次改 `release_year`，没问用户想搜"发行年"还是"收听年"
2. 改了不验证 → 每次改完没本地跑 API 直接重启服务，连续崩了两次

**根因：** 数据结构经历多次变化（年度表→单表→流派中间表），我脑子里没有当前状态的稳定地图就开始改代码。

**承诺的改进流程（album-tracker 核心查询改动）：**
1. 先想清楚需求（发行 vs 收听）
2. 写出完整 SQL 逻辑
3. 本地 Python 先跑通
4. 再改 server.ts + 编译 + 重启 + 验证
